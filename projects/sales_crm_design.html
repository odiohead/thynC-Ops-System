3. 데이터 모델

3.1 hospital_sales_profiles (변경)

유지: stage_id(영업 단계) · owner_id(씨어스 담당) · total_beds/total_wards · sales_memo — next_action / next_action_date 삭제

3.2 persons / person_affiliations (신설 — hospital_contacts 대체)

테이블컬럼
persons (인물 마스터 — 병원 독립)name(필수) · person_group_id → PERSON_GROUP(의사·간호·의공·전산·구매·원무·기타) · specialty(진료과) · phone · email · memo · is_active
person_affiliations (병원 소속 이력)person_id FK(CASCADE) · hospital_code FK · title(직책) · department · is_primary(주요) · is_current · started_on/ended_on · note — 인덱스 (hospital_code,is_current)·(person_id)
  • 전원 처리: 액션 1회 — 기존 소속 종료(is_current=false·ended_on) + 새 병원 소속 생성. 예: 신촌세브→용인세브 이동 시 용인세브 목록에서 과거 이력 표시 = 리드 신호
  • hospital_contacts는 DROP (현재 0행)

3.3 sales_deals (차수 축 — 확장)

컬럼상태비고
deal_code / hospital_code+round_no UNIQUE / status_id / contract_date / project_code / remark / ward_count / bed_count유지
wards_text / depts_text신설도입병동(IM, ICU… 콤마 다중)·도입진료과 — 엑셀 핵심 공백
hospital_model_id / seers_model_id신설판매모델 2관점 — 둘 다 SALES_MODEL 단일 마스터(설정 제어). 차수마다 달라도 됨 = 혼재 허용
amount_product / amount_construction / amount_actual교체제품가·공사비·실판매액(BIGINT 원). '판매' = 제품+공사 파생 표시. 용역매출은 0행 → 제외
tax_invoice_id / settlement_id신설세금계산서 발행·정산 — 차수 단위 관리
intro_type_id / amount_total / amount_service삭제도입형태는 판매모델 2필드가 대체(운영 도입형태는 프로젝트 조인), 금액 2필드 → 3필드

3.4 projects (운영 축 — 최소 추가)

education_date(교육일, DATE) — 프로젝트 폼·상세 노출. 영업 축은 조인 표시만

SALES_DEAL_STATUS (유지)협의중·계약완료·해지중단O

SALES_MODEL (신설)구축형·구독형·분납형·사용량비례형X
SALES_TAX_INVOICE (신설)미발행·발행완료·씨어스 계약X
SALES_SETTLEMENT (신설)미정산·진행중·완료X
PERSON_GROUP (신설)의사·간호·의공·전산·구매·원무·기타X
