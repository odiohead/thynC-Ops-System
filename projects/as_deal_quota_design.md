# AS 접수 상세 — 계약건별 도입 기기수량 · AS 교체 현황 (상품유형 한도 관리)

> 상태: **PROD 반영 (2026-11-02)** — 2026-11-02 사용자 승인("제안대로 진행, 한도는 일단 비율만") → 같은 날 **라이트 한도 100% 확정**(§8). 구현 위치는 AS 접수 상세 '1. 공통정보' 카드.

## 1. 취지
- 라이트형은 AS(교체) 수량에 정책 제한이 있어, AS 접수를 처리하는 시점에 **이 병원이 계약건별로 도입한 기기 수량**과 **지금까지 교체해 준 수량**을 같은 화면에서 봐야 한다.
- 예: A병원 1차 일반형 심전계 30/산소포화도 30, 2차 라이트 심전계 10/산소포화도 10 도입. 교체 이력 일반 심전계 4·산소포화도 2, 라이트 심전계 3·산소포화도 3 → **라이트 심전계 `3 / 10`**.
- 기존 기능과의 관계: 분실 접수의 '구분' 필드(기기군별 교체 제공/구매수량, 10% 한도)는 **분실 전용**이고 상품유형 구분이 없다. 병원 상세 '도입 현황'(디바이스 원장 요약)은 배치 대수 중심이라 AS 교체 누계가 없다. 이 기능은 그 사이를 메운다.

## 3. 표현 (1. 공통정보 카드, '구분' 옆 새 필드 **'도입·AS 교체 현황'**)
```
도입·AS 교체 현황                              [계약건 2건 ▸]
            심전계           산소포화도
일반        4 / 30 (13%)     2 / 30 (7%)
라이트      3 / 10 (30%)     3 / 10 (30%)   ← 처리 시 4 / 10 (40%)
```
- **행 = 상품유형(일반 / 라이트 / 미지정은 교체가 있을 때만)**, 열 = 기기군(심전계 / 산소포화도 — `asDeviceGroupOf` 단일 소스). 셀 = `교체 누계 / 도입 수량 (%)`.
- **이 접수 포함**: 분실 '구분'과 같은 규칙 — 이 접수의 미종결 라인 전부 + 교체 확정 라인을 더한 값을 `→ 처리 시 n / m`으로 뒤에 표기(종결 접수면 '이 접수 포함').
- **계약건 펼침**: 우측 상단 `[계약건 n건 ▸]`을 누르면 딜 행 목록 — `1차 일반 · 2025-05-29 · 심전계 30 · 산소포화도 30` / `2차 라이트 · 2026-08-25 · 심전계 10 · 산소포화도 10` — 도입 수량의 출처를 보여 주는 용도. 기본은 접힘(초기 단순화 원칙).
- 분모 없음: 상품유형의 계약완료 딜은 있는데 기기 수량 행이 없으면 `n / 미등록`, 계약완료 딜 자체가 없으면 필드에 '계약완료 계약건 없음' 한 줄.
- 한도 표시: 라이트 행이 정책 한도를 넘으면(또는 이 접수 처리 시 넘으면) 분실과 같은 빨간 테두리 깜박임 + 배지 — **한도값·적용 대상은 §6 ①에서 결정**(미정이면 비율만 표시, 경고 없음).
- 모든 접수 구분(고장·분실)에 표시. 분실 접수에서는 기존 '구분' 필드의 분실 한도 표기와 나란히 놓인다(분실 한도는 그대로).

## 4. 산식 (`lib/asDealQuota.ts` — 단일 소스, `asLostQuota` 패턴)
- **분모** `도입 수량[상품유형][기기군]` = 이 병원의 **계약완료 딜**(`status_codes.name='계약완료'`)을 `sales_deals.product_type`으로 묶어 `sales_deal_devices.quantity`를 `device_info` 기기군별 합산. product_type NULL인 딜은 '미지정' 상품유형.
- **분자** `교체 누계[상품유형][기기군]` = 이 병원의 AS 라인 중 `outcome='REPLACE'`(취소 접수·취소 라인 제외, **이 접수 제외**)를 교체된 기기(`as_receipt_items.device_id → hospital_devices.product_type`)의 상품유형으로 집계. 기기 미연결 라인(3건)은 '미지정'.
  - 분실 접수의 교체도 포함할지는 §6 ②. 수리반환(REPAIR_RETURN)은 '교체'가 아니므로 제외(분실 접수의 수리반환=제공 규칙은 분실 한도 쪽에만 적용).
- **이 접수분** = 이 접수의 미종결 라인(outcome NULL) + 교체 확정 라인을 같은 방식으로 상품유형 판정(라인 기기의 원장 상품유형; 미등록 라인은 접수 시 입력한 상품유형이 있으면 그 값, 없으면 '미지정').
- 계약건별 교체 수는 **산출하지 않는다**(§2 — deal_code 75%·잡음). 계약건 펼침은 도입 수량 출처만.

## 6. 검토 포인트 (승인 전 결정)
① **라이트 한도** — 정책값이 무엇인지(예: 도입 수량의 n% 또는 n대), 일반형에도 한도가 있는지. 미정이면 1차는 비율 표시만
② **분자에 분실 교체 포함 여부** — 라이트 "AS 수량 제한"이 고장 교체만인지, 분실 교체까지인지(분실은 별도 10% 한도가 이미 있음). 제안: **고장 교체만**, 분실은 기존 필드가 담당
③ **표 위치·기본 상태** — 공통정보 '구분' 옆 2×2 표 + 계약건 접힘(제안) vs 계약건 행을 항상 펼침
④ 교체된 기기의 상품유형이 원장에 '미지정'인 경우 처리 — '미지정' 행으로 노출(제안) vs 일반으로 간주

## 8. 라이트 한도 100% (2026-11-02 사용자 정책 확정)
- 정책: **라이트형은 도입 기기 수량의 100%까지만 교체 허용**. 일반형은 한도 없음(비율만). `AS_LITE_REPLACE_QUOTA_PCT = 100`(`lib/asReceiptShared.ts`)
- 판정(라이트 행 셀 단위): `overBefore` = 교체 누계 > 도입×100% (이미 초과) / `overAfter` = 누계+이 접수분 > 도입×100% (이 건 처리 시 초과). 도입 수량 미등록(null)이면 판정 안 함. 요약 `liteOverBefore`·`liteOverAfter`
- 표시 2곳: ① 필드 영역 — 분실 한도와 같은 빨간 테두리 깜박임 + 배지('라이트 교체 수량 초과' / '이 건 처리 시 라이트 한도 초과' / 종결이면 '이 접수 포함 …'), 해당 셀 빨간 굵게 ② **상단 상시 배너**(red, role=alert — 기존 작업 결과용 amber 경고 배너 위) — 문구 '라이트형 교체 수량 초과 — 도입 수량의 100%를 이미 넘었습니다' 또는 '이 건 처리 시 라이트형 교체 수량이 도입 수량의 100%를 초과합니다' + 기기군별 `누계 / 도입 → 처리 시 n / m (%)`
- dev2 검증: 실제 초과 사례 없음(라이트 딜 병원 4곳 전부 false) → HOSP-000042 라이트 딜 산소포화도 도입 수량을 임시 1로 낮춰 `before 1/1 after 2 → liteOverAfter=true`, 0(행 제외)으로 낮춰 `introduced null → 판정 없음` 확인 후 30 원복

## 9. 상단 알림 영역 통합 + 정책 모달 (2026-11-02)
- 사용자 질문 "상단 알러트는 기존 컴포넌트 재사용?" → 아니었음(기존 amber 배너는 작업 결과 일회성, 새 red 배너는 상시) → **한 컴포넌트 `app/as-receipts/_components/AsNoticeArea.tsx`로 통합**하되 목적별 분기: `alerts`(상시 정책 알림 — red, 닫기 없음) / `warnings`(작업 결과 — amber, [닫기])
- 추가 요청 "상단 배너를 페이지 안 팝업으로?" → 조건부 채택: 정책 알림 키가 **처음 나타날 때 1회** 페이지 안 모달(오버레이, ⚠ 정책 확인 필요, [확인]·ESC·배경 클릭으로 닫힘). 닫은 뒤에도 red 배너는 남는다. 같은 키는 컴포넌트 생존 중 재표시 없음(입고처리·확정 후 재조회에도 모달 안 뜸). 키에 셀 값(`누계/도입`)을 포함해 상태가 달라지면 다시 1회 띄움
- 사용자 추가 요청(같은 날): **작업 결과 경고(amber)도 동일하게 모달 1회 → 배너** — 새 결과가 올 때마다 모달(ℹ 작업 결과 확인 — 경고 n건), 닫으면 amber 배너([닫기]) 유지. 정책 알림과 동시에 나타나면 한 모달에 두 섹션(헤더는 red)
- 사용자 정정(같은 날): "기존 배너" = **채널톡 변경 감지 패널**(진입 시 주황, 반영/새 접수 분리/무시 버튼). 작업 결과 모달은 유지하고 채널톡도 동일하게 → 세 번째 종류 `panels`(조치형): 패널 컴포넌트를 배너 자리와 **모달 안에 그대로 렌더**(모달에서 바로 조치), 키 최초 1회, 조치로 패널이 사라지면 모달도 닫힘. 헤더 톤 red(정책) > orange(조치형) > amber(작업 결과). 테스트 레코드 dev2 AS-202610-0450·0453(변경 항목 2건)
- 정책 알림 `alerts` 2종: **분실 제공 한도 10%**(분실 접수, `lostQuota` — 사용자 지적 AS-202610-0415 심전계 22/191=11.5% 이미 초과인데 모달 없었음 → 같은 날 추가) + **라이트 교체 한도 100%**(전 구분, `dealQuota`). 둘 다 필드 표시(빨간 테두리·배지)와 같은 판정, 상단 red 배너 + 최초 1회 모달
- dev2 임시 임계치 5%로 확인(HOSP-000042 AS-202610-0408 라이트 SpO2 1/30 → 2/30) 후 100 원복
