## 1. 이 화면이 답해야 할 질문

AS업무는 접수 담당(CX)·수리 담당(리프레시센터)·출고(자재)·영업/병원 담당·품질(개발)·관리자가 같은 데이터를 서로 다른 질문으로 본다. 화면을 지표 목록이 아니라 **질문 4개**로 나눴다.

| 탭 | 질문 | 주로 보는 사람 |
|---|---|---|
| **현황** | 지금 무엇이 얼마나 쌓여 있고 어디에 막혀 있나 | 접수·수리·발송 담당(매일), 팀장 |
| **기간 분석** | 얼마나 들어오고 나갔나, 어떻게 처리됐고 얼마나 걸렸나 | 팀장·관리자(주간·월간 보고) |
| **병원별** | 어느 병원에서 많이 발생하나, 분실·라이트 한도는 괜찮은가 | 영업·병원 담당, 정책 관리 |
| **기기·품질** | 어떤 기기가 얼마나 고장나고, 고친 뒤에도 다시 들어오나 | 품질·개발, 수리 담당 |

공통 필터는 **기간 · 구분(고장/분실) · 기기군(심전계/산소포화도) · 병원** 4개. 병원을 고르면 4개 탭 전체가 그 병원 기준이 된다(= "병원별 건수 조회"). '현황'만 기간을 쓰지 않는다(조회 시점 스냅샷).

## 2. 기존 기능과의 관계 (중복 검토)

| 기존 | 이 화면과의 관계 |
|---|---|
| AS 목록 상단 요약 스트립(진행 중·이번 주·평균 처리일·2주 경과) | 목록의 필터 진입용으로 유지. 대시보드 '현황'의 진행 중·2주 경과는 **같은 정의**를 써서 같은 숫자 |
| 수리대기 큐(`/as-receipts/queue`) | 작업 화면. 대시보드는 큐의 버킷 판정(`asQueueBucketWhere`)을 그대로 불러 **대수만** 보여 주고 큐로 링크 |
| VOC·AS 주간 대시보드(`/voc/dashboard`) AS 구역 | **금~목 주간 보고용**(전주 대비·8주 추이·주간 PDF). 이 화면은 임의 기간·운영 현황·병원 드릴다운용. 겹치는 지표(수리출하 소요·병원 TOP)는 같은 정의. 하단에 상호 링크만 둠 |
| 병원 상세 'AS 현황' 블록, AS 상세 '구분'·'도입·AS 교체 현황' | 병원 1곳의 한도 표시. 대시보드 '병원별'은 **전 병원 한도 현황을 한 표로**(신규) — 산식은 기존 함수와 동일(스모크로 대조) |

스키마 변경 없음 · 신규 테이블 없음 · 쓰기 없음(읽기 전용).

## 3. 지표 정의 (단일 소스 = `lib/asDashboard.ts`)

### 3.1 공통 규칙
- **미종결 접수** = 상태 없음 또는 `ticket_status ∉ (RESOLVED, CLOSED)` — 목록 요약과 동일
- **물량**에서 '취소' 접수·라인취소(`CANCELED`) 제외 — VOC·AS 주간 대시보드와 동일
- **기기군** = `asDeviceGroupOf`(원장 모델명 → 미등록 기기종류 → 시리얼 접두). SQL로 재구현하지 않고 라인을 읽어 JS에서 접는다
- **귀속 기준일**: 접수 = `receipt_date`, 완료 = `resolved_at`, 발송 = 라인 `shipped_at`, 회수기기 처리 = 라인 `repaired_at` (전부 DATE, KST 달력일)
- **기기군 필터**: 라인은 그 기기군만, 접수는 그 기기군 라인을 1대 이상 가진 건만
- **직전 대비** = 같은 길이의 바로 앞 기간

### 3.2 현황 (조회 시점)
| 지표 | 정의 |
|---|---|
| 진행 중 접수 / 기기 | 미종결 접수 건수 / 그 접수의 라인취소 제외 라인. 보조: 결과 미확정 라인 |
| 오늘·이번 주 접수 | 접수일 기준(취소 포함 — 목록 '이번 주 접수'와 동일), 주 시작 = 월요일 |
| 2주 경과 미처리 | 미종결 ∧ 접수일 < 오늘−14일 (목록 `overdue=1`) |
| 확인필요 | 목록 `needsCheck=1`과 같은 SQL(`findAsNeedsCheckReceiptIds` — 목록 라우트에서 lib로 이동해 공용화) |
| 등록대기 | `as_intake_links` PENDING (필터 무관 전체) |
| 단계별 진행 현황 | AS_STATUS 마스터의 미종결 상태별(0건도 표시) 접수·기기, **접수 후 경과일 4구간**(3일 이내/4~7/8~14/15일 이상), 단계 체류 중앙값(`status_changed_at` 이후 일수), 최장 경과 |
| 입고 예정 · 수리 대기 (대) | 수리대기 큐 버킷 그대로(`asQueueBucketWhere` + `asDeviceGroupWhere`) |
| 발송 대기 (대) | 미종결 **고장** 접수 ∧ 결과 미확정 ∧ 미발송 ∧ (회수기기 처리 끝남(폐기 제외) ∨ 선교체 접수) |
| 분실 처리 대기 (대) | 미종결 **분실** 접수의 결과 미확정 라인 — 출고요청 진행 / 미처리 |
| 가장 오래된 진행 중 접수 | 접수일 오래된 순 10건 |
| 진행 중 접수가 많은 병원 | 병원별 미종결 접수 상위 10곳(2주 경과·최장 경과) |

### 3.3 기간 분석
| 지표 | 정의 |
|---|---|
| 접수(건·대) | 접수일이 기간 안 (취소 제외) |
| 완료(건) · 미처리 증감 | 상태 '완료' ∧ 완료일이 기간 안 · 미처리 증감 = 기간 내 접수(취소 포함) − 종결(완료+취소) |
| 발송(대) | 발송일이 기간 안인 라인 |
| 접수→발송 (헤드라인) | 기간 안에 발송된 수리반환·교체 라인의 `발송일 − 접수일`(달력일) 중앙값·상위 10%(p90). 구분 필터가 분실이면 분실, 아니면 고장 |
| 교체율(고장) | 기간 내 고장 접수 라인 중 교체 ÷ (교체 + 수리반환) |
| 선교체 요청 | 기간 내 고장 접수 중 선교체 태그 비율 |
| 추이 | 간격 자동(45일 이하 일 / 210일 이하 주(월요일 시작) / 그 이상 월) + 수동 선택. 막대 = 접수(고장·분실 적층), 선 = 완료(건) 또는 발송(대) — **같은 단위끼리만 한 축**(이중 축 없음). 차트/표 전환 |
| 처리 결과 | 기간 내 접수 라인의 현재 결과(진행 중·수리반환·교체·분실종결·미회수·되찾음·라인취소) × 고장/분실 |
| 소요일 표 | 고장·일반 / 고장·선교체 / 분실 × 접수→입고 · 입고→발송 · 접수→발송. 단계 분해는 **일반 고장만**(선교체는 발송이 입고보다 앞서고 분실은 입고가 없음). 접수→완료(접수 건) 별도 |
| 접수→발송 분포 | 고장·일반, 5구간(3일 이내/4~7/8~14/15~21/22일 이상) |
| 구성 | 유입 경로(`source`) · 수거 방법 · 발송 방법 · 태그 |

> 입고일(라인 `received_at`)은 입고 대조 도입(2026-09) 이후에만 있다 — 그 이전 기간은 접수→입고·입고→발송이 '—'.

### 3.4 병원별
- 표 행 = 기간 내 접수가 있거나, 지금 미완료가 있거나, **한도를 초과한** 병원(접수가 없어도 한도 현황이 빠지지 않게)
- 열: 접수(건) · 기기(대) · 고장 · 분실 · 심전계 · 산소포화도 · 교체 · 접수→발송 중앙값 · 미완료(조회 시점) · 배치 기기(기기현황 ACTIVE) · 100대당 접수 · 한도
- **한도**(기간 무관 누적): 분실 제공 누계 ÷ 구매수량(한도 10%, `computeAsLostQuotaAll`) · 라이트 고장 교체 누계 ÷ 라이트 도입 수량(한도 100%, `computeAsLiteQuotaAll`). 병원 1곳 함수와 같은 정의의 일괄판
- 정렬(모든 열) · 병원명 검색 · [한도 초과만] · [미완료 있는 병원만] · CSV 내려받기 · 25곳씩 페이지
- **병원 선택 시**: 요약 한 줄 + 한도 현황(분실·상품유형×기기군) + 병동별 접수 대수(접수 때 적힌 병동) + 기간 내 접수 목록(최근 100건) + 병원 상세·AS 목록 링크

### 3.5 기기·품질
| 지표 | 정의 |
|---|---|
| 기기군별 | 고장·분실 대수, 교체·수리반환, 교체율, 배치 기기, **배치 100대당 고장** |
| 상품유형별(고장) | 기기현황 배치의 상품유형(일반/라이트/미지정) |
| 재접수율 | 기간 내 고장 접수 라인(정상 형식 시리얼) 중 **같은 시리얼의 이전 고장 접수**가 있는 비율(전체 이력) |
| 수리 후 30일 내 재접수 | 이전 접수에서 수리반환으로 발송된 날(가장 최근)로부터 30일 안에 다시 고장 접수된 라인 — 수리 품질 신호 |
| 재접수까지 걸린 기간 | 재접수 라인의 `이번 접수일 − 직전 고장 접수일` 4구간(30일 이내/31~90/91~180/181일 이상) |
| 반복 접수 기기 | 기간 내 접수 시리얼 중 누적 고장 접수 횟수 상위 15대 → 시리얼 검색 링크 |
| 회수기기 처리 | 처리일이 기간 안인 라인의 수리/문제없음/폐기, 문제없음 비율, 처리자별 대수 |
| 접수사유 키워드 | 자유 입력 사유를 접수 건 단위로 7개 키워드군에 매칭(느낌표·측정·전원·센서·접촉/연결·파손·분실) — **참고 수치**, 복수 해당 가능 |

## 4. 화면 구성

```
[AS 대시보드]                                   집계 21:40 [새로고침] [← AS업무]
┌ 기간 (7일)(30일)(90일)(이번 달)(지난 달)(올해)(전체) [직접 지정]  구분 [전체|고장|분실]  기기군 [전체|심전계|산소포화도]  병원 [검색] ┐
 현황 | 기간 분석 | 병원별 | 기기·품질
 (탭의 질문 한 줄)
 ┌ 숫자 한 줄 (칸을 누르면 해당 목록) ┐
 ┌ 주 블록 1~2개 ┐ ┌ 보조 블록 ┐
```
- 숫자는 **카드 나열이 아니라 한 띠(StatStrip)** 안의 칸으로. 탭마다 블록 3~4개 이내
- 빈 상태에서도 표 머리·단계 행(0건)·차트 축이 그대로 보인다
- 필터·탭은 URL 동기화(`tab`·`range` 또는 `from`/`to`·`category`·`group`·`hospital`) — 링크 공유·새로고침 복원
- 드릴다운: 숫자 칸·단계 행 → AS 목록(상태·구분·기기군·병원 필터를 옮겨 감), 대수 칸 → 수리대기 큐, 병원명 → 병원 필터, 접수번호 → 접수 상세, 시리얼 → 시리얼 검색
- 차트 색: 고장 파랑 / 분실 주황 / 흐름선 청록(범주 3색, 라이트·다크 각각 색각·대비 검증), 경과일 4구간은 한 색상의 밝기 순서. 글자는 계열색을 쓰지 않음

## 5. API

`GET /api/as-receipts/dashboard?section=now|period|hospitals|quality&from=YYYY-MM-DD|all&to=&category=FAULT|LOST&group=ECG|SPO2|ETC&hospital=<병원코드>&granularity=day|week|month`
- 권한: AS업무 열람과 동일(로그인). 읽기 전용
- 탭 하나가 섹션 하나를 부른다(탭 전환 시 지연 로딩, 같은 조건은 화면에서 캐시)
- 응답 `{ section, filter(해석된 기간·병원명), generatedAt, data }`
- dev2 실측(접수 4,164·라인 16,156): now 약 200ms · period 80ms · hospitals 30~100ms · quality 45ms
