## 2. 전체 구도 — 2데이터셋 + 운영 축 조인

```
┌─ ① 병원 축 (병원당 1세트) ───────────────────────────────┐
│  영업 프로필: 단계·씨어스 담당·전체 병상/병동·메모        │
│  인적정보: 인물(직군·진료과·연락처) × 소속 이력(전원 처리)│
│  도입현황(파생): 차수 수·누적 병동/병상·누적 실판매액·침투율│
├─ ② 차수 축 (도입 1건 = 딜 1행, 1차·2차·N차) ─────────────┤
│  규모: 도입병동/진료과·병동수·병상수                      │
│  계약: 판매모델(병원/씨어스)·계약일·상태                  │
│  금액: 제품가·공사비·실판매액 (판매합계는 파생)           │
│  정산: 세금계산서 발행·정산 상태                          │
├─ 운영 축 (기존 — 저장 없이 조인 표시) ────────────────────┤
│  단계(공사상태)·답사일·공사시작/완료·납품·교육일(신설)·   │
│  지역·종별·오더현황                                       │
└──────────────────────────────────────────────────────────┘
```

원칙(유지): 빈 상태에도 필드·컬럼 상시 노출 / 기존 축 재사용·이중 저장 금지 / 파생값(판매합계·침투율) 저장 안 함

### 3.1 hospital_sales_profiles (병원 축 — 변경)

### 3.2 persons / person_affiliations (병원 축 — 신설, hospital_contacts 대체)
**persons (인물 마스터 — 병원 독립)**: name(필수) · person_group_id → StatusCode `PERSON_GROUP`(의사·간호·의공·전산·구매·원무·기타) · specialty(진료과) · phone · email · memo · is_active

**person_affiliations (병원 소속 이력)**: person_id FK(CASCADE) · hospital_code FK · title(직책) · department(부서) · is_primary(주요 인물) · is_current · started_on / ended_on · note
- 인덱스: (hospital_code, is_current), (person_id)
- **전원 처리**: 기존 소속 is_current=false + ended_on 기록 → 새 병원 소속 행 생성 (액션 1회). 신촌세브 → 용인세브 사례: 용인세브 인물 목록에서 과거 신촌세브 이력이 보임 = 리드 신호
- hospital_contacts는 **DROP** (현재 0행 — 이전 부담 없음)

### 3.3 sales_deals (차수 축 — 확장)
| 컬럼 | 상태 | 비고 |
|---|---|---|
| deal_code / hospital_code+round_no UNIQUE / status_id(SALES_DEAL_STATUS) / contract_date / project_code / remark | 유지 | |
| ward_count / bed_count | 유지 | 도입규모 스냅샷 |
| **wards_text / depts_text** | 신설 | 도입병동(IM, ICU… 콤마 다중)·도입진료과 — 엑셀 핵심 공백 |
| **hospital_model_id / seers_model_id** | 신설 | 판매모델 2관점, 둘 다 → StatusCode `SALES_MODEL` **단일 마스터**(설정 제어·값 증가 대응). 차수마다 달라도 됨 = 병원 내 혼재 허용 |
| **amount_product / amount_construction / amount_actual** | 교체 | 제품가·공사비·실판매액 (BIGINT 원). '판매'합계 = product+construction **파생 표시**. 엑셀 실사용 분석 근거(용역매출 0행 → 제외) |
| **tax_invoice_id / settlement_id** | 신설 | 세금계산서 발행(SALES_TAX_INVOICE)·정산(SALES_SETTLEMENT) — 차수 단위 관리 (결정 4-2) |
| ~~intro_type_id / amount_total / amount_service~~ | 삭제 | 도입형태는 판매모델 2필드가 대체(운영 도입형태는 연결 프로젝트에서 조인), 금액 2필드는 3필드로 교체 |
