## 1. 이 기능이 답해야 할 질문

| 질문 | 답하는 섹션 |
|---|---|
| 이 병원은 언제, 어떤 조건으로 들어왔나 (계약·구축·기기) | 2. 보고서 배경 |
| 도입 이후 무슨 일이 있었나 (연혁) | 3-1) 운영 연혁 |
| AS는 얼마나, 어떤 기기에서, 얼마나 빨리 처리됐나 | 3-2) AS 현황 |

| 지금 열려 있는 일과 데이터가 비어 있는 곳은 어디인가 | 5. 이슈/리스크 |
| 그래서 무엇을 해야 하나 | 4. 검토 결과 · 6. 결론 및 요청사항 |

## 2. 범위

**1차 포함**: 병원 1곳 단위 '운영 이력 보고서' 1종 · 병원 검색 → 생성 → 웹 미리보기 → Word 다운로드 · 생성 이력(재열람) · 레포트 전용 AI 설정(모델·effort)

**1차 제외 (후속)**: 다른 보고서 종류(월간 VOC·병원 비교 등) · 예약/일괄 생성 · 위키 문서(주간업무 등) 반영 · PDF 출력 · 최고관리자 외 권한 개방

## 3. 핵심 원칙 — "숫자는 코드가, 글은 AI가, 모양은 양식이"

1. **수치·표는 전부 코드(SQL)가 만든다.** 매번 같은 결과가 나오고 검증할 수 있다. AI는 숫자를 만들지 않는다. 11/07 참고 보고서와 시스템 수치가 어긋났던 것처럼 보고서에서 가장 위험한 오류가 숫자이기 때문
2. **AI는 정해진 칸만 채운다.** 응답은 구조화 출력(JSON 스키마)으로 받고, 칸마다 길이 제한을 둔다. 레이아웃·목차·표는 AI가 바꿀 수 없다 → 사용자 요구 "AI가 생성하더라도 포맷·구성 동일"
3. **웹과 Word는 같은 문서 모델 하나를 그린다.** `ReportDoc`(블록 배열: 제목·문단·표·목록) 하나를 웹 렌더러와 docx 렌더러가 각각 그리므로 화면과 다운로드가 어긋나지 않는다
4. **생성 결과는 스냅샷으로 저장한다.** 다운로드는 화면에 보였던 그 스냅샷으로 만든다 (다시 조회해 숫자가 바뀌는 일 없음). 새로 만들려면 [다시 생성]

## 4. 화면 — `/reports` (최고관리자 전용)

초기 버전은 단순하게(축 1개): **병원 검색 + 생성 이력 목록 → 보고서 보기**

```
┌ 레포트 ────────────────────────────────────────────────┐
│ 병원 운영 이력 보고서                                     │
│ [병원명/코드 검색 ▾        ]  [보고서 생성]               │
│                                                          │
│ 최근 생성 이력                                            │
│ 생성일시 │ 병원 │ 상태 │ 모델·effort │ 생성자 │            │
│ (비어 있으면 "아직 생성한 보고서가 없습니다")              │
└──────────────────────────────────────────────────────┘
```

- 병원 검색은 기존 병원 검색 컴포넌트 재사용(`app/m/_components/HospitalSearch.tsx` 패턴, PC용으로 이동·공용화)
- [보고서 생성] → `/reports/[id]`로 이동. 생성 중에는 단계 표시(데이터 수집 → AI 분석 → 완료). AI 단계는 1~3분 걸릴 수 있음
- 보고서 화면 `/reports/[id]`: A4 세로 비율의 '종이' 영역에 양식 그대로 렌더 + 상단 도구줄 [Word 다운로드] [다시 생성] / 문서번호 입력란(D1)
- AI 단계가 실패해도 코드 섹션(배경·내용 표·미결·데이터 점검)은 그대로 보이고, AI 칸에는 "AI 분석 실패 — [AI만 다시 실행]"
- 모바일 대응: 보기 전용(가로 스크롤 없이 표 축소), 생성은 PC 기준

## 7. AI 분석 — 단발 호출 1회 (도구 없음)

- **방식**: 에이전트 루프가 아니라 **한 번의 요청**. 필요한 사실을 미리 다 모아 넣으므로 도구 호출이 필요 없음 (빠르고 비용 예측 가능)
- **입력**: ① `facts` 요약(숫자 섹션 그대로, JSON) ② 본문 말뭉치 — VOC(코드·접수일·분류·제목·본문·처리내용, 각 800자 상한), 채널톡 봇 요약, 유지보수 증상·조치, AS 수리 소견 상위 유형. 말뭉치 상한(초기 15만 자)을 넘으면 최근 순으로 자르고 **잘린 건수를 비고에 기록**(조용히 자르지 않음)
- **출력**: 구조화 출력 `output_config.format`(JSON 스키마) — 2차(2026-11-08): `summary`(3문단, ≤1200자) · `groupNotes[{group, note}]`(VOC 대분류별 확인된 내용) · `themes[{name, vocCodes[], insight}]`(≤8) · `keyIssues[{vocCodes[], issue, ask, action}]`(≤6) · `asProcess`(AS 처리 흐름 한 줄, 근거 없으면 빈 문자열) · `insights[{title, detail}]`(시사점 ≤5). 1차의 `risks`·`recommendations`는 `insights`로 통합
- **서버 검증**: vocCodes·vocCode가 실제 이 병원 VOC인지 확인(아니면 버림) · AI 문장 속 숫자가 facts에 없는 값이면 경고로 비고에 표시(차단하지 않음) · `stop_reason`이 `refusal`/`max_tokens`면 AI 실패 처리
- **호출 형태**: `client.messages.stream(...).finalMessage()` · `thinking: { type: 'adaptive' }` · `output_config: { effort, format }` · `max_tokens` 32000 · 시스템 프롬프트 고정(캐시 가능)
- **refusal 대비**: Opus 5.5 계열 권장대로 서버 측 `fallbacks: "default"`(beta) 적용 예정 — 현재 SDK 0.88 타입에 없어 구현 시 SDK 업그레이드 또는 타입 확장으로 처리(구현 전 확인)

### 7.1 레포트 전용 AI 설정 (어시스턴트와 별도)

- AppSetting 키 `ai_report_settings` = `{ model, effort }` — 기존 `ai_assistant_settings`와 분리
- **모델은 코드 허용 목록에서 선택**(현 설정 원칙 유지 — 자유 입력은 오타 하나로 전 요청 404): `claude-opus-5-5`(기본) · `claude-opus-5` · `claude-sonnet-5-5`
- **effort**: `low` · `medium` · `high`(기본) · `max` (SDK 0.88 지원 범위. `xhigh`는 SDK 업그레이드 후 추가). 분석·종합 글쓰기라 기본 `high` — Opus 5.5의 API 기본값은 `medium`이므로 항상 명시 전송
- 화면: 설정 > AI 어시스턴트 페이지에 **'레포트' 섹션 추가**(D3) — 모델 드롭다운 + effort 라디오 + "건당 예상 비용" 안내
- 사용량: `ai_usage_logs`에 기록, 구분 컬럼 `feature`(`assistant`/`report`, 기본 `assistant`) 추가 → 기존 AI 사용량 화면에서 레포트 비용 분리 집계

### 7.2 비용 감 (참고)

제주한라 규모(VOC 72·AS 18) 기준 입력 약 3~4만 토큰, 출력(사고 포함) 약 1~2만 토큰 → Opus 5.5($4/$20 per 1M, 2026-10 기준 단가)로 **건당 약 0.3~0.6달러**. VOC 수백 건 병원은 입력 상한까지 약 1달러 내외. 실측 후 설정 화면 안내 문구 확정
