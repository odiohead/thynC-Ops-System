# 사용량 — 전체 병원 대시보드 필터 · 저장된 보기 (종별 · 병원 지정 · 기간) 설계안

> 2026-11-26 개정: '병원군'을 **저장된 보기**(조건 묶음에 이름을 붙여 저장 · 목록에서 눌러 보기 · 공유)로 바꿈 — 사용자 의견 "대시보드 템플릿 개념, 저장하면 어딘가 리스트업해 놓고 클릭해서 보기, 공유하면 모두가 고를 수 있고 안 하면 내 리스트에만".

## 1. 요청과 이 화면이 답해야 할 질문

사용자 요청(2026-11-26): 대시보드에 **필터** 개념을 넣는다.

1. **종별로 나눠 보기** — 상급종합 · 종합병원 · 병원 · 요양병원이 각각 얼마나 쓰는가
2. **몇 개 종만 골라 보기** — 예: 종합병원과 병원만 놓고 전체 수치 · 순위를 보고 싶다
3. **내가 정한 병원 묶음으로 보기** — 담당 병원, 관심 병원 묶음. 그리고 그렇게 맞춘 화면을 **이름을 붙여 저장해 두고 눌러서 다시 보기**(공유하면 모두가 고를 수 있다)
4. **기간** — 지금은 12주 추이만 보인다. 더 길게, 구간을 정해서, 또는 전체를 보고 싶다(기본은 12주)

지금 대시보드의 선택은 기기와 판매모델 두 가지뿐이고, 추이는 12주로 고정이다.

참고 — 수집 중인 병원의 종별 분포(2026-11-26, 188곳): 병원 91 · 종합병원 82 · 요양병원 8 · 상급종합 6 · 의원 1.

## 2. 검토가 필요한 결정 (제안값)

| # | 결정 | 제안 | 이유 · 대안 |
|---|---|---|---|
| F1 | 필터가 적용되는 범위 | **화면 전체** — 핵심 수치 · 추이 · 분포 · 상위/하위 · 변화 · 점검 · 표가 모두 고른 병원만으로 다시 계산된다 | 영역마다 대상이 다르면 숫자가 서로 맞지 않는다. 기기 · 판매모델 선택과 같은 방식 |
| F2 | 종별 고르기 | **여러 개 선택**(아무것도 고르지 않으면 전체). 종별 목록은 수집 중인 병원에 있는 것만 | "종합병원 + 병원" 같은 조합을 한 번에 |
| F3 | 종별로 **나눠** 보기 | **'종별 가동률' 영역 추가** — 종별마다 병원 수 · 가동률 · 이전 30일 대비. 줄을 누르면 그 종별로 필터 | 고르기(F2)와 비교하기는 다른 일이다. 판매모델별 3줄과 같은 형태 |
| F4 | **저장된 보기** (사용자 의견 반영 2026-11-26) | 지금 화면의 **조건 묶음**(기기 · 판매모델 · 종별 · 병원 지정 · 추이 기간)에 이름을 붙여 저장한다. 저장한 보기는 화면 위쪽에 **목록으로 나열**되고 누르면 그 조건으로 바뀐다. **'공유'를 켜면 사용량을 볼 수 있는 모두의 목록에, 끄면 내 목록에만** 보인다. 수정 · 삭제는 만든 사람과 ADMIN 이상 | 병원 묶음만 따로 저장하는 것보다 "이 조건으로 본 화면"을 통째로 저장하는 쪽이 쓰는 방식에 맞다(티켓 목록의 '저장된 뷰'와 같은 개념 — 그쪽은 브라우저에만 저장돼 공유가 안 된다). 공유가 필요해 표가 하나 생긴다 |
| F5 | 병원 묶음을 만드는 법 | 필터 줄의 **'병원 지정'** 에서 병원을 고른다(이름 검색 · 종별 단위로 한꺼번에 담기 · 병원 태그에서 가져오기). 고른 병원 목록은 다른 조건과 함께 보기에 저장된다 | 병원 묶음을 따로 관리하는 화면을 두지 않는다 — 묶음은 보기의 일부다. 표에서 한 줄씩 체크하는 방식은 190곳에서 번거롭다 |
| F5-1 | 보기를 연 뒤 조건을 바꾸면 | 목록의 그 보기 옆에 '바뀜' 표시 + **[저장]**(내 보기 · 권한이 있는 공유 보기) / **[새 보기로 저장]** | 남의 공유 보기를 실수로 덮어쓰지 않게 |
| F5-2 | 처음 열 때의 보기 | **항상 조건 없는 '전체'** — 기본 보기 지정은 넣지 않는다 | F9와 같은 이유. 필요하면 2차로 |
| F6 | **기간이 바꾸는 것** | **추이의 범위만** — 12주(기본) · 26주 · 52주 · 전체 · 직접 지정. 가동률 · 순위 · 증가/감소 판정은 지금처럼 '최근 30일 대 이전 30일' 고정 | 가동률의 정의가 병원별 화면(최근 30일)과 같아야 숫자를 서로 맞춰 볼 수 있다. 대안 — 기준 기간 자체를 고르기(예: "10월의 순위"). 정의가 화면마다 달라지고 판정 규칙도 다시 정해야 해서 필요가 확인되면 2차로 |
| F7 | 긴 기간의 눈금 | 26주까지는 **주 단위**, 그보다 길면 **월 단위** | 52개 점은 읽기 어렵다 |
| F8 | '전체'의 실제 범위 | 일별 집계가 있는 첫 날부터 — 지금은 **2026-08-23부터** | 병원 서버가 기기 기록을 종료 후 90일만 보관해 그 이전은 만들 수 없다. 앞으로는 계속 쌓인다 |
| F9 | 필터 상태 보관 | **주소에 담는다**(그 주소를 보내면 같은 화면 — 저장된 보기는 `view=번호`). 마지막에 쓴 필터를 기억하는 것은 넣지 않는다 | 열 때마다 전체가 기본이어야 숫자를 오해하지 않는다 |
| F10 | 지역 · 병원 태그 필터 | **이번에는 넣지 않는다** | 요청에 없고, 원하는 묶음은 병원 지정으로 만들 수 있다. 병원 태그('주요병원' 4곳 등)는 병원을 지정할 때 '태그에서 가져오기'로만 쓴다 |

## 3. 화면

### 3.1 보기 목록과 필터 줄

```
보기  [전체] [수도권 종합병원 ⚑] [내 담당 병원] [요양 · 산소포화도 ⚑] …더보기      [+ 지금 조건을 보기로 저장]
       ↑ 지금 고른 보기는 채워서 표시 · ⚑ = 공유된 보기

기기 [심전계|산소포화도|카트온]   판매모델 [합산|일반형|사용량비례형]

종별 [전체 ▾]   병원 지정 [없음 ▾]   추이 기간 [12주 ▾]                  병원 73곳 기준 · 필터 지우기
      ☑ 종합병원       검색 …                 ● 12주
      ☑ 병원           ☑ ○○병원               ○ 26주
      ☐ 상급종합       ☑ △△병원               ○ 52주
      ☐ 요양병원       종별로 담기 · 태그에서   ○ 전체 (08-23 ~)
      ☐ 의원           가져오기                ○ 직접 지정…
```

**보기 목록** (맨 위 한 줄)
- 내 보기와 공유된 보기를 한 줄에 나열한다(내 것 먼저). 누르면 그 보기의 조건이 필터 줄과 화면 전체에 적용된다. 맨 앞의 '전체'는 조건 없는 기본 화면이다.
- 줄에 다 들어가지 않으면 '더보기'에서 내 보기 · 공유된 보기로 나눠 전부 보여 준다(이름 검색, 만든 사람 표시).
- **[+ 지금 조건을 보기로 저장]**: 이름과 공유 여부만 묻는다. 저장되는 것은 지금의 기기 · 판매모델 · 종별 · 병원 지정 · 추이 기간이다.
- 보기를 연 뒤 조건을 바꾸면 그 보기에 '바뀜' 표시가 붙고 [저장] · [새 보기로 저장] · [되돌리기]가 나온다. 남의 공유 보기는 [새 보기로 저장]만 된다.
- 보기마다 ⋯ 에서 이름 바꾸기 · 공유 켜기/끄기 · 삭제(만든 사람과 ADMIN 이상).

**필터 줄**
- 고른 조건은 줄 오른쪽에 **"병원 N곳 기준"** 으로 요약하고, 조건이 하나라도 있으면 '필터 지우기'를 보여 준다.
- 핵심 수치의 제목에도 조건이 붙는다 — 예: "전체 심전계 가동률 · 종합병원 · 병원".
- 종별과 병원 지정을 함께 고르면 **둘 다 만족하는 병원**만 남는다.
- 좁은 화면에서는 줄이 바뀌고(보기 목록은 옆으로 넘겨 본다), 고르는 창은 아래에서 올라오는 창으로 연다.

### 3.2 종별 가동률 (새 영역 — 추이 · 분포 줄에 함께)

```
종별 가동률                                  병원 수 · 최근 30일 · 이전 30일 대비
상급종합   ████████░░░░░░░░   41.2%    6곳   ↑ +2.1%p
종합병원   █████░░░░░░░░░░░   24.8%   82곳     −0.3%p
병원       ████░░░░░░░░░░░░   19.5%   91곳     −0.9%p
요양병원   ██░░░░░░░░░░░░░░   10.3%    8곳     +0.4%p
```

- 종별마다 전체 가동률과 같은 방식(Σ 평균 최대 동시 ÷ Σ 수량)으로 낸다.
- 줄을 누르면 그 종별 하나로 필터가 걸린다. 병원을 지정해 둔 상태면 그 안에서의 종별 구성을 보여 준다.
- 병원이 1~2곳뿐인 종별도 그대로 보여 준다(병원 수가 옆에 있다).

### 3.3 추이

- 제목이 고른 기간을 따른다 — "전체 가동률 26주 추이", "전체 가동률 추이 · 2026-09-01 ~ 2026-10-31".
- 직접 지정은 기존 날짜 범위 선택기(`DateRangeFilter`)를 쓴다. 시작이 집계 첫 날보다 앞이면 첫 날로 맞춘다.
- 주 단위 · 월 단위 모두 지금과 같은 규칙(그 구간에 값이 있는 병원끼리 Σ 평균 최대 동시 ÷ Σ 평균 수량)이고, 점에 올리면 병원 수가 함께 나온다.
- 표의 병원별 작은 추이(12주)는 그대로 둔다.

### 3.4 병원 지정

- 필터 줄의 '병원 지정'을 누르면 고르는 창이 열린다: 이름 검색, 종별 단위로 한꺼번에 담기, 병원 태그에서 가져오기, 고른 병원 목록과 개수.
- 수집을 시작하지 않은 병원도 담을 수 있다(수집을 시작하면 그 보기에 나타난다). 지정했지만 수집 중이 아닌 병원 수를 창에 표시한다.
- 저장하지 않고 한 번만 보는 데도 쓸 수 있다(주소에는 병원 코드 목록이 담긴다).

### 3.5 저장된 보기에 담기는 것

| 조건 | 저장 형태 |
|---|---|
| 기기 · 판매모델 | 고른 값 그대로 |
| 종별 | 고른 종별 목록(없으면 전체) |
| 병원 지정 | 병원 코드 목록(없으면 지정 없음) |
| 추이 기간 | 12주 · 26주 · 52주 · 전체는 **그 말 그대로** 저장(열 때마다 오늘 기준으로 다시 잡힌다). 직접 지정은 날짜 그대로 |

표의 정렬 · 검색어 · 표 필터(증가 · 감소 등)는 저장하지 않는다 — 보는 동안의 조작이다.

## 4. 계산과 API

### 4.1 필터는 서버에서 건다

- `GET /api/usage/overview`에 `types`(종별, 쉼표로 여러 개) · `hospitals`(지정한 병원 코드) · 추이 범위(`weeks=12|26|52`, `range=all`, `from` · `to`)를 더한다. `view=번호`를 주면 서버가 그 보기의 조건을 읽어 적용한다(주소에 따로 적은 조건이 있으면 그것이 우선 — '바뀜' 상태).
- 서버가 대상 병원을 먼저 정하고, 그 병원들만으로 지금의 계산(`summarizeOverview` · `summarizeOverviewTotal` · `summarizeOverviewTrend` · `summarizeOverviewActivity`)을 돌린다. **계산 규칙은 바꾸지 않는다** — 들어가는 병원 목록만 달라진다.
- 응답에 추가: 병원마다 `hospitalType`, 종별 요약 `byType`(종별 · 병원 수 · 전체 한 줄), 적용된 필터와 고를 수 있는 값(`filters`: 종별 목록과 병원 수, 집계 첫 날). 보기 목록은 따로 받는다(4.3).
- 수집 범위(운영 병원 대비)도 같은 조건의 운영 병원을 분모로 한다 — 예: 종합병원 필터면 "운영 중인 종합병원 N곳 중 수집 M곳".

화면에서 걸러 다시 더하는 방식은 쓰지 않는다. 신규 측정 수 · 수집 범위처럼 서버가 합쳐서 주는 값이 있어 화면에서 다시 계산할 수 없고, 같은 규칙을 두 곳에 두게 된다.

### 4.2 긴 추이

- 12주까지는 지금처럼 병원별 일별 값을 읽어 계산한다(순위 · 판정에 어차피 필요한 범위).
- 그보다 긴 추이는 **구간(주 · 월)별 합만** DB에서 묶어 가져온다 — 병원 190곳 × 1년치 일별 행을 화면을 열 때마다 읽지 않기 위해서다. 묶는 규칙은 `summarizeOverviewTrend`와 같아야 하므로, 겹치는 12주 구간에서 두 결과가 같은지 검사로 고정한다.
- 수신이 끊긴 병원은 지금처럼 마지막 수신일 뒤의 날을 뺀다.

### 4.3 저장된 보기 (본체 DB, 일반 마이그 절차)

```
usage_dashboard_views
  id          번호
  name        이름 (만든 사람 안에서 중복 불가)
  owner_id    만든 사람 (users)
  is_shared   공유 여부
  filters     조건 묶음 — { device, model, types[], hospitals[], trend: { weeks | all | from · to } }
  created_at · updated_at
```

- API: `GET /api/usage/views`(내 보기 + 공유된 보기, 만든 사람 이름 포함) · `POST`(만들기) · `PATCH/DELETE /api/usage/views/[id]`.
- 권한: 사용량 열람 권한이 있으면 만들고 볼 수 있다. 수정 · 삭제 · 공유 켜기/끄기는 만든 사람 또는 ADMIN 이상. 공유하지 않은 남의 보기는 목록에 나오지 않고 번호로도 열리지 않는다.
- 조건 묶음은 저장할 때 서버가 다시 검사한다(모르는 기기 · 종별 · 날짜 형식 거부, 병원 코드 수 상한).
- 병원 목록에서 지워진 병원 코드는 읽을 때 무시한다. 만든 사람의 계정이 비활성이 되어도 공유된 보기는 남는다(ADMIN 이 정리).

## 5. 달라지지 않는 것

- 가동률 · 판정 · 순위의 정의, 병원별 화면, 일별 집계의 구조와 주기
- 원본 DB · 수신부 · Agent

## 6. 검증 계획

1. 순수 함수: 종별 요약, 주 · 월 구간 묶기, 긴 추이의 DB 집계 = 일별 값 계산(겹치는 구간)
2. dev2 실제 화면(PROD 집계 사본 188곳): 종별 하나 · 여러 개 · 병원 지정 · 둘 함께에서 핵심 수치 · 순위 · 분포 · 표가 같은 병원 집합으로 다시 계산되는지(API와 대조), 종별 줄을 누르면 필터, 기간 5종의 추이 범위 · 눈금, 주소로 다시 열었을 때 같은 화면, 390px · 다크
3. 저장된 보기: 저장 → 목록에 나타남 → 누르면 조건 적용 · 주소에 `view` → 조건을 바꾸면 '바뀜'과 저장 · 새 보기로 저장 · 되돌리기, 공유를 켜면 다른 계정의 목록에 나타나고 끄면 사라짐, 남의 공유 보기는 수정 · 삭제 불가(화면 · API), 공유하지 않은 남의 보기는 번호로도 열리지 않음
4. 필터가 없을 때 지금 화면과 숫자가 같은지

## 7. 진행 순서 (승인 후)

1. 서버 필터(종별 · 병원 지정) + 종별 가동률 영역 + 추이 기간 — 표 추가 없이 가능
2. 저장된 보기(표 · API · 보기 목록 · 저장/바뀜 처리)
3. dev2 검증 → DEV → PROD (보기 표는 마이그 필요 — PROD는 명시 허락 후)

## 8. 이번 범위가 아닌 것

- 기준 기간 자체를 고르는 기능(F6의 대안), 지역 · 태그 필터(F10), 기본 보기 지정(F5-2)
- 병원별 화면의 기간 선택 확대(지금 30일 · 90일)
- 대시보드 내보내기(엑셀 · 이미지)

### 9.2 설계에서 구체화된 것

- **긴 추이도 일별 값을 읽어 같은 함수로 계산한다.** DB에서 따로 묶는 조회를 만들지 않았다 — 고른 판매모델의 일별 행만 기간만큼 더 읽고(1년이면 병원 190곳 × 365행), 구간 계산은 `summarizeOverviewBuckets` 하나다. 규칙이 한 곳에만 있다.
- **보기 관리 창이 '더보기'를 겸한다.** 줄에는 앞의 6개(보는 중인 보기는 항상)만 놓고, 나머지는 관리 창에서 열거나 고친다.
- **종별 가동률은 병원 지정 안에서 전 종별을 보여 준다.** 종별 필터를 걸어도 줄지 않고(비교용), 고르지 않은 종별은 흐리게 한다.
- 보기를 연 뒤 조건을 바꾸면 주소에 `view=번호` + 바뀐 조건만 붙는다. 종별을 전부 지운 경우처럼 빈 값도 적어야 '보기의 값을 덮었다'가 전해진다(`types=`).
- 한 사람이 만들 수 있는 보기는 50개, 한 보기의 병원은 500곳까지.
