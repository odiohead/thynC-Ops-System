# 출고업무 Slack 알림 — 등록·완료 전용 채널 + 요청자 멘션

> **상태: 구현 완료 (dev2, 2026-11-02) — PROD 배포 대기** (결정 D1~D4 반영)
> 상위: `domain_event_notify_design.md`(도메인 이벤트 카탈로그 + `notifyDomainEvent` + `notify_routes`). 티켓 공통 알림(`notifyTicketCreated/Changed`)은 이번 범위 밖 — Slack 알림 전면 검토는 별도 작업.

---

## 1. 요청 (사용자, 2026-11-02)

1. 출고요청으로 출고업무가 생성되면 지정 채널로 Slack 알림
2. 출고업무가 처리 완료되면 지정 채널로 **요청자를 태그**해 Slack 알림
3. 출고업무 전용 Slack 채널 지정

## 2. 현황 (PROD 2026-11-02 읽기 전용 확인)

- 알림 구조는 이벤트 카탈로그(`lib/notify-events.ts`) × 라우팅 규칙(`notify_routes` — 이벤트·업무유형·그룹·Sev 조건 → 채널, 멘션 옵션 none/그룹 구성원/@here/@channel). 새 알림 = 카탈로그 항목 1개 + 발생 지점 `notifyDomainEvent()` 1줄(선례 AS 입고확인)
- 출고업무는 현재 **티켓 공통 규칙으로만** 나간다: 생성 → '전체 티켓 등록'(TICKET_CREATED, 그룹 구성원 멘션), 상태 변경 → '전체 상태 변경'(TICKET_STATUS_CHANGED) — 둘 다 **'운영 공지' 채널**에 다른 업무와 섞여 발송. 출고업무 전용 이벤트·채널 없음
- 멘션 옵션에 '요청자'가 없다 → 2번은 코드 보완 필요
- 발송 채널 3개 등록(운영 공지 / SLA 지연 / AS업무). 출고업무 전용 채널 없음
- 출고업무 상태: 요청 → 처리중 → 보류 → 완료 / 취소. '완료'는 [출고 처리](fulfill — 재고 출고·기기현황 등록 후 자동 '완료') 또는 상태 직접 변경으로 진입
- PROD 출고업무 누적 1건(완료) — 사실상 신규 운영

## 3. 설계

### 3.1 이벤트 2종 신설 (카탈로그 그룹 '출고업무')

| key | 라벨 | 발생 지점 | 멘션 |
|---|---|---|---|
| `STOCK_OUT_CREATED` | 출고요청 등록 | 출고요청 생성 (`POST /api/stock-out-requests`) | 규칙의 멘션 옵션 |
| `STOCK_OUT_COMPLETED` | 출고 완료 | 상태가 '완료'로 **진입**할 때 — 출고 처리 실행·상태 직접 변경 공통(이미 완료인 건 재저장은 미발송, 취소는 미발송) | **요청자 고정 태그** + 규칙의 멘션 옵션 |

- 둘 다 `notifyDomainEvent()` 경유(단일 소스 규칙 유지 — 도메인 라우트에서 채널 직접 발송 없음). 이벤트 사용 여부·채널은 설정 > Slack 알림 화면에서 관리
- 조건 축: Assignment Group·Sev(기존 도메인 이벤트와 동일)

### 3.2 요청자 태그

- `notifyDomainEvent` 입력에 `mentionUserIds`(선택) 추가 → 시스템 계정의 Slack ID로 `<@U…>` 한 줄(이메일로 자동 매핑·캐시 — 기존 담당자 멘션과 같은 함수). 개인 Slack 알림을 끈 사용자·매핑 실패 시 이름만 표기
- 요청자 = 출고요청 등록자(`created_by`)

### 3.4 채널·규칙 (설정 — 코드 아님)

1. 발송 채널에 출고업무 전용 채널 등록(Slack 채널 ID, 봇 초대 필요)
2. 라우팅 규칙 2개: `STOCK_OUT_CREATED` → 출고 채널, `STOCK_OUT_COMPLETED` → 출고 채널
3. (권장) 공통 규칙 '전체 티켓 등록'·'전체 상태 변경'의 업무유형에서 출고업무를 빼서 운영 공지 채널과 중복 발송 방지
