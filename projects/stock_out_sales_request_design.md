# 출고요청 — 영업 유형(평가용·판매용·오산영업소) 모바일 등록

> 상태: **dev 구현 완료 (2026-11-05 — 모바일 + PC 등록, DEV 빌드 반영·PROD 미반영)** — 사용자 기능정의(2026-11-05) 기반. 출고업무 v2(`stock_out_v2_design.md`) §1의 "② 영업·사업 측면의 비주기 자재출고" 갈래를 영업 유형 3종으로 구체화한다.

## 1. 배경
- 기존 출고요청은 프로젝트 상세 팝업에서만 생성(구축 BUILD, 프로젝트 필수)
- 영업 현장에서 데모·심포지엄·영업용 제공·분실기기 제공 등 **프로젝트 없는 출고**를 모바일로 바로 요청하고, 등록 즉시 출고업무(STOCK_OUT) 티켓으로 자재 담당자에게 넘기려 함

## 2. 사용자 기능정의 → 결정
| 항목 | 정의 | 구현 |
|---|---|---|
| 유형 | 평가용 / 판매용 / 오산영업소 | 업무 구분 `purpose`에 `EVALUATION`·`SALES`·`OSAN_OFFICE` 추가 (기존 BUILD·MAINTENANCE·BUSINESS 유지) |
| 목적 | 평가용: 데모·심포지엄·기타 / 판매용: 영업용 제공·분실기기 제공 / 오산영업소: 시연용(심포지엄 등) — 1개라 자동 | `sub_purpose` 코드, 어휘는 `lib/stockOutShared.ts` `STOCK_OUT_SUB_PURPOSES` (코드 고정) |
| 납품처 | 병원(검색 선택) / 기타(텍스트) | `dest_type` HOSPITAL·OTHER, `dest_hospital_code`(FK hospitals) / `dest_text` |
| 수령지·수취인 | 텍스트 | `ship_address`, `recipient` |

| 등록 | 출고업무 도메인에 티켓 생성 (모바일 + PC 출고업무 [출고요청]) | 기존 `POST /api/stock-out-requests` 확장 — 레코드+라인+티켓 단일 트랜잭션, '출고요청 등록' Slack 도메인 이벤트 그대로 |
| 가이드 | 각 항목 타이틀 하단 가이드, 설정에서 수정 | 설정 > 출고 품목 관리 > **입력 가이드** 탭 (app_settings `stock_out_request_guides` JSON, 비우면 기본 문구) |

## 3. 데이터 모델 — 마이그레이션 `20261105120000_stock_out_sales_request`
- `stock_out_requests.project_code` NOT NULL 해제 + CHECK `kind`: 영업 유형이면 `project_code IS NULL AND sub_purpose·dest_type NOT NULL`, 그 외 업무는 `project_code NOT NULL` (기존 요청 영향 없음)
- 신규 컬럼 `sub_purpose`·`dest_type`·`dest_hospital_code`·`dest_text`·`ship_address`·`recipient`, CHECK `dest`(병원이면 코드, 기타면 텍스트 필수)
- `purpose` CHECK 2곳(`stock_out_requests`·`stock_out_item_purposes`)에 3유형 추가

## 4. 노출 초기값 — `scripts/seed-stock-out-masters.sql` 2-b (멱등)
- 유형별 인벤토리(평가용재고·판매용재고·오산영업소)의 MC200M-T·MP100W·MP1000F·MP2000F·MP2000R·MGW1010·전극 + thynC운영팀재고 배터리·에바폼 = 유형당 9종
- 유형별로 이미 한 행이라도 있으면 건너뜀 → 관리자가 해제한 품목을 재실행으로 되살리지 않음

## 5. 화면
- **모바일** `/m/stock-out-requests` 내 영업 유형 출고요청 목록 + [새 출고요청] · `/new` 등록 폼(유형 → 목적 → 납품처 → 수령지·수취인 → 희망 출고일 → 품목 수량 → 비고, 항목 제목 아래 가이드, 하단 고정 등록 버튼) · `/[id]` 읽기 전용 상세. 뷰어는 등록 불가
- **PC** (2026-11-05 사용자 요청 "출고업무 우측 상단 [출고요청]") 목록 우측 상단 **[+ 출고요청]**(뷰어 숨김) → `StockOutRequestFormModal` 영업 유형 모드(project 미지정): 유형 칩 → 목적 칩(오산영업소 자동) → 납품처 병원/기타(`DestHospitalSearch` 전체 병원 검색) → 수령지·수취인 → 희망 출고일 → 품목(유형 탭 노출 품목, 인벤토리→분류) → 비고 → 첨부(엑셀 등), 항목 아래 입력 가이드. **프로젝트(구축) 유형은 여기서 만들지 않음** — 프로젝트 상세 전용. 목록에 '구분' 필터(전체·구축·평가용·판매용·오산영업소), '프로젝트 / 유형'·'병원 / 납품처' 열 · 상세: 유형·목적·납품처·수령지·수취인, [수정]은 같은 모달(유형은 고정, 목적·납품처·수령지·수취인·희망일·품목·비고 수정)
- **설정** 출고 품목 관리: 탭 구축·유지보수·사업업무·**평가용·판매용·오산영업소**·구성 안내·**입력 가이드**

## 6. 처리·연동
- 티켓 제목 단일 소스 `stockOutTitle()` — 프로젝트명 또는 `유형·목적 납품처` (예: `[출고요청] 평가용·데모 서울대학교병원`), 티켓 병원 = 납품처 병원(기타면 없음)
- 출고 처리(`lib/stockOutFulfill.ts`): 출고 대상 = 프로젝트 병원 또는 납품처. 전표 출고처 = 병원명/납품처 텍스트, `workType`·`refCode`는 프로젝트 요청만. **기기현황 등록은 병원 납품처일 때만** (기타 납품처는 배치 병원이 없어 생략)
- Slack 알림: 머리줄 = 납품처명, '업무 구분'에 목적 병기, 수취인 줄 추가
- 기기현황 등록: 병원 납품처면 유형 무관 등록(용도 평가용재고·오산영업소→평가용, 판매용재고→판매용) — 2026-11-05 사용자 확인 '모두 등록'
